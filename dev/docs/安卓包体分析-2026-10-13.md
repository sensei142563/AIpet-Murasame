# 安卓包体分析：302 MB 是谁占的、能省多少（2026-10-13 实测）

> 起因：Phase 4 构建验收时发现 `app-release.apk` 仍有 **302 MB**、debug **313 MB**，
> 与"删掉 Chaquopy 后 APK 会更小"的预期不符。本文是**拆包实测**的账。
> 数据来源脚本：`dev/scripts/apk_size_breakdown.py`（可直接重跑）。
> APK：`chatter/app/build/outputs/apk/debug/app-debug.apk`（2026-10-13 19:47 构建）

## 一、账目（按占用排序）

| 占用 | 是什么 | 能不能省 |
|---|---|---|
| **228.15 MB** | `assets/asr-sensevoice/model.int8.onnx` —— 离线语音识别模型（SenseVoice int8） | ⚠ **是真功能，不能直接删**；但可改为**按需下载**（省 228 MB） |
| 72.76 MB | `assets/pets/murasame/` —— 丛雨的 Live2D + 立绘 + 表情包 + 语音 | 可做纹理压缩/精简重复帧 |
| 59.96 MB | `classes*.dex` —— Kotlin/Java 代码（**debug 未混淆**） | ✅ **release 开 R8** 可显著缩小 |
| 31.11 MB | `lib/arm64-v8a` —— `libonnxruntime.so` 20.68 + `libsherpa-onnx-*.so` 8.79 | 必需（只保留 arm64 已做） |
| **24.13 MB** | `assets/asr-zh-14M/*.onnx` —— **第二套** ASR 模型（zipformer 14M） | ✅ **已无引用，可删**（见下） |
| 6.20 MB | `assets/Murasame/*` —— 与 `assets/pets/murasame/` **重复**（同一张 `texture_00.png` 3.81 MB 存了两遍） | ✅ 去重可省 |
| 5.8 MB | `assets/noir/*` —— 另一个角色（同样有 `noir/NOIR/` 重复一份） | ✅ 去重可省 |
| 1.4 MB | `assets/voice/murasame` + `assets/vad/silero_vad.onnx` 等 | 保留 |

`app/src/main/assets` 目录总计 **343.47 MB**（构建前），是全仓唯一的大头。

## 二、三条可立刻执行的（按性价比）

### ① release 打开 R8（一行配置，先做）
`app/build.gradle:47` 当前是 `minifyEnabled false` —— 这也解释了为什么
release(302 MB) 只比 debug(313 MB) 小 11 MB。打开混淆 + 资源压缩后，`classes*.dex`（60 MB）
应显著缩小。
```gradle
release {
    minifyEnabled true
    shrinkResources true
    proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
}
```
> ⚠ 打开前先确认真机回归通过（混淆可能影响反射/序列化）。**建议作为"发版前"的一步**。

### ② 删掉已无引用的第二套 ASR 模型（省 24 MB）
证据：
- `OnlineAsr.kt:16` 注释自述换模型历史："最初是 **streaming-zipformer-zh-14M**（tiny 级，效果一般）
  → bilingual zipformer（流式）→ 现在 SenseVoice（非流式）"；
- 全仓代码检索 `asr-zh-14M` / `zh-14M` / `zipformer`：**只有这条注释**，没有任何加载它的代码。

⇒ `assets/asr-zh-14M/` **可以直接删**（24.13 MB）。删之前建议再全局搜一次
（含 `build.gradle`、`CMakeLists.txt`、`.gradle` 配置），确认无引用。

### ③ 把 SenseVoice 改成"按需下载"（省 228 MB，**收益最大**）
先纠正一个容易犯的误判：**它不是死代码**。
- `OnlineAsr.kt` 是它的模块（`DIR = "asr-sensevoice"`，`MODEL = "model.int8.onnx"`）；
- `ChatScreen.kt:619/634` 真的在调 `OnlineAsr.offlineEnabled(ctx)` / `recognizeWav(...)`；
- `SettingsPage.kt:108/128` 有开关与自检；
- `WakeWord.kt:6` 明确写着"手机端已经有**本地 STT**（SenseVoice，**实测 0.94**）"。

它的问题是**在部分真机上初始化解崩**（`OfflineTtsEngine.kt:38` 记："同机的 SenseVoice（离线识别）
则是初始化解崩掉进程"；`OnlineAsr.kt:33` 同样记了 MIS-AL00 / Android 12 的实测），
所以代码里已经有 `offlineEnabled(ctx)` 这样的**门控**。

⇒ 正确做法不是删功能，而是**把模型从 APK 里拿出来**：
- **A. 首次使用时下载**（推荐）：`OnlineAsr` 本来就把 assets 里的模型**复制到 filesDir**
  再交给 sherpa（`OnlineAsr.kt:50-57`）—— 把"从 assets 复制"换成"从网络下载到 filesDir"
  是**同一段代码的自然延伸**，改动小、省 228 MB；
- **B. Play Asset Delivery / AAB 资源包**：上架路线可用，但本地分发（直接发 APK）不适用；
- **C. 换小模型**：当年那套 tiny zipformer 就是"效果一般"才换掉的，**不建议回退**。

## 三、另外两条（可选）

- **去重**：`assets/Murasame/` 与 `assets/pets/murasame/live2d/` 是同一套 Live2D 的两份拷贝
  （`texture_00.png` 3.81 MB ×2）；`assets/noir/NOIR/` 同理。确认没有老代码按旧路径读之后可删，
  约省 6~8 MB。
- **角色素材按需**：`assets/pets/murasame` 72.76 MB 全是角色资源。若将来多角色，
  建议"默认只带一个角色 + 其余下载"，否则每加一个角色 APK 就涨几十 MB。

## 四、结论

| 动作 | 工作量 | 省 |
|---|---|---|
| release 开 R8 + 资源压缩 | 一行配置 + 一次回归 | dex 60 MB 的大部分 |
| 删 `assets/asr-zh-14M` | 删目录 + 复搜 | **24 MB** |
| SenseVoice 改按需下载 | 中（改复制逻辑为下载 + 校验） | **228 MB** |
| 素材去重 | 小（先确认无旧路径引用） | 6~8 MB |

**保守估计**：做完 ②③ 两条，APK 可从 **302 MB → 约 50 MB 量级**（不含角色素材优化）；
再做完 ①④ 还能更低。**这是个值得排进安卓段的明确任务。**

## 五、⚠ **更正**：`assets/Murasame/`（6.54 MB）**不能删**（我上一轮的建议是错的）

上一轮我在"三、另外两条"里写"`assets/Murasame/` 与 `assets/pets/murasame/live2d/` 是同一套的两份拷贝，
确认没有老代码按旧路径读之后可删，约省 6~8 MB"。**核实后发现该判断不成立**，按原文更正如上。

### 证据（这次搜了 C/C++，上一轮只搜了 kt/java/xml/json/txt —— 漏了 native 侧）
```
app/src/main/cpp/LApp/JniBridgeC.cpp:121
    // 下标对应 LAppLive2DManager::_modelDir（assets 根目录里含 <dir>/<dir>.model3.json 的目录，按名排序）。

app/src/main/cpp/LApp/LAppLive2DManager.cpp:92
    const char MODEL3_JSON[] = u8".model3.json";
app/src/main/cpp/LApp/LAppLive2DManager.cpp:294-299
    // model3.jsonのパスを決定する.
    // ディレクトリ名とmodel3.jsonの名前を一致していることが条件
    modelJsonName += ".model3.json";
```

⇒ **native C++ 侧会扫 assets 根目录**，把"含 `<dir>/<dir>.model3.json`"的目录收集成 `_modelDir`（**按名排序**），
再由 JNI 用下标选择模型。`assets/Murasame/` 里正好有 `Murasame.model3.json` + `Murasame.moc3` + `Murasame.4096/`
+ `motion/` —— 它就是**原生渲染器的模型目录**。

### 结论（两份拷贝服务两个消费方，不是重复）
| 拷贝 | 消费方 | 能不能删 |
|---|---|---|
| `assets/Murasame/`（6.54 MB，24 个文件） | **native C++**（`LAppLive2DManager` 扫 assets 根目录） | ❌ **不能删**，删了 Live2D 渲染会坏 |
| `assets/pets/murasame/live2d/`（15.35 MB） | Kotlin 侧（`File(File(baseDir,"pets"), activePet())`） | ❌ 不能删 |
| `assets/noir/NOIR/`（嵌套一份，2.89 MB） | 需同样方式核实（`noir/noir.model3.json` 是否存在） | ⏳ 未核实，**别猜** |

> 教训：**判断 assets 是否死文件时，必须把 native（cpp/h/cpp/hpp）一起搜** ——
> 这一层的路径常常是**拼出来的**（`.model3.json` 是常量拼接），纯文本搜索也未必命中原样字符串，
> 要看**扫描逻辑**而不是只看引用。

### 真正安全的去重方式（如果将来要做）
不是删目录，而是**改 native 侧的扫描根**：让 `LAppLive2DManager` 从 `pets/<id>/live2d/` 找模型，
然后把 `assets/Murasame/` 移走。**这是代码改动 + 必须真机验证**，属于"等你确认后再动"的一类，
不在低风险清单里。
