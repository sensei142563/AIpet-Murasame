# 导师反馈的拆解与我们该怎么接（2026-10-13）

> 背景：导师在群里就"AI 桌宠创业"提了一串问题与判断。用户要求："老师说的可能有些地方在画饼，
> 但是有的值得注意"。本文把**该接住的**与**该打折扣的**分开，并给出可执行的下一步。
>
> **写作纪律**：不写学校/学院/专业/姓名/导师姓名；不把没查到证据的东西写成结论。

## 一、必须接住的（导师戳中的真问题）

### 1）"有什么是我们有、其他人没有的？"——这是全文最硬的一句
它把"功能最全"这类回答直接判为不合格。原因很朴素：
**功能清单是可复制的，价值主张不可复制。** 说"我最全"等于把比赛拖进清单对轰，
而清单永远有人在补。

⇒ 我们要给的不能是一张更长的表，而是**一个窄、但别人短时间补不上**的点，
其余功能降级为"支撑这个点的证据"。

### 2）"GPT 出来后一周就能搓出一个手机 App"——这一刀最狠，而且**成立**
它直接废掉了"我们上了手机"作为卖点。用户当时的回答（"便携"）被导师判为 weak，
**判得对**：便携性是**平台属性**，不是**我们的属性**——任何人都能上手机。

⇒ 手机端可以留在故事里（它是**分发与场景**），但**不能当 unique 点**。

### 3）"得有证据和调研"——这一条正是我们能立刻交卷的地方
我们**已经有**两份带来源的调研：
- `docs/桌面宠物市场调研-功能对比.md`（开源/Steam 两类 + 《你妈》为什么火 + 共性 + 缺口 + 存疑清单）
- `docs/AI桌宠-聊天机器人方向调研.md`（协议端/应用层/数字人 + "桌宠×QQ 打通"到底有多少人做 + 证据强弱分级）

而且写法符合导师的口味：**带"未查证/存疑"清单**，而不是只报喜。

⇒ 但**有三个导师点名的对标，我们一份都没查**（全仓 0 命中）：
`仓鼠元元`（北大团队）、`WorkBuddy`、`和平精英`（游戏联动）。这三个必须补，
否则导师一问"你连我说的这个都没看"就崩。

### 4）AR 这一条：导师的判断比我们更冷，但**方向对**
导师原话："手机实景可互动的 AR 暂时不太推荐……AR 这个技术目前不是特别成熟；大部分都是 demo 形式"。
结合他举的例子（3D 人体设备 + NVIDIA 端侧 GPU 一台 7000+），他的意思是**别把主线压在 AR 上**。

⇒ 诚实面对：我们最近几轮把手机端手部互动（检测/命中/捏合/握拳/挥手/视线）做完了，
**技术上成立、编译与 151 个单测全绿**，但**它的战略地位不高**。
处理方式：**不删**（它是"我们真能做出来"的能力证明），
但**不从它开场、不让它当故事中心**。

### 5）"我们缺少一个漂亮的、讲给别人听别人愿意投资的故事"
这与用户任务里的"总之要讲好故事"是同一句话。现在的问题是：
21 页大纲已经把"功能展示 + 实现方法 + 未来规划"铺好了，
但**开头缺少那句一击即中的定位**——第 7 页现在的诚实定位（"整合者，而非首创者"）
在**学术/自审场合**是加分（可信），在**要投资/要评奖的场合**是自杀。

⇒ 需要按听众准备**两个版本的开场**（见第四节）。

### 6）"人机交互蛮像的，可以看看 UbiComp/IMWUT、CHI、CSCW"
这不是客套，是**指路**。它意味着另一条可能的"unique"：
把桌宠当**人机交互研究**做（而不是当 App 做），能讲出研究贡献的题目有：
常驻陪伴的感知与打扰边界、长期记忆对用户关系感知的影响、
非摄像头感知（隐私友好）在陪伴场景里的接受度……**这正是我们的毫米波那条线**。

## 二、该打折扣的（"画饼"或不精确，别照单全收）

| 导师的话 | 我的折扣 |
|---|---|
| "技术很硬核也行（大疆无人机）" | 大疆的护城河是**十年 + 硬件/飞控/供应链**堆出来的。把它当**方向**可以，当**计划**不行。我们的资源曲线不支持"技术硬到别人做不到"这种叙事。 |
| "软硬件结合"（第一张图） | 导师自己后面就说"玩偶/投影这些都是周边"。而且硬件是**烧钱的**——7000+ 的端侧 GPU 就是例子。学生项目的硬件路线应当**只做到"可演示的原型"**，不做量产叙事。 |
| "大厂入局（探索更长粘性的 C 端入口）" | 趋势对，但**现在还没有能打的成品**；大厂进来反而给我们"需求被验证"的背书。不必恐慌，但要引用**具体产品**而不是泛泛说"大厂都在做"。 |
| 合作者拿到 workshop 的 best paper | 值得恭喜，**但导师自己也说了"虽然只是 workshop"**。它证明的是"这条路能走"，不是"我们已经在这个水平"。引用时别夸大。 |
| "必须有一个非常明显的 unique 点" | 方向对，但**执行上最容易走歪**：为了"有 unique"而硬造概念，一问就穿。正确做法是**先找证据**，把"真的比别人强的那一小块"证明出来，而不是发明一块。 |

## 三、我们的 unique 点，可能在哪（诚实候选 + 证据要求）

> 原则：**只列"能拿证据对质"的候选**，并按"别人补上的难度"排序。

### 候选 A：**非摄像头的常驻感知（毫米波）** ← 我看最像真壁垒
- 为什么可能是壁垒：它需要**硬件 + 信号处理 + 场景适配**，不是一周能搓的；
  而且"不用摄像头"在居家陪伴场景里是**隐私叙事**，评委和用户都听得懂。
- 为什么正对导师的指路：UbiComp/IMWUT 这一路最吃"新感知模态 + 真实场景"。
- 我们的现成条件：课题里有完整装置（服务帕金森动作识别），
  课题结束后可迁移——**迁移路径要写清楚**（先输出标准参数流 → 桌面侧驱动 → 再谈移动）。
- 需要补的证据：**他人在陪伴场景用过毫米波吗**？用过做到什么程度？——**必须查**，否则不许写。

### 候选 B：**二次元垂直深度（角色一致性）** ← 导师已经半认可
- 导师原话："二次元？这个可以深入，这样的话属于我们对于二次元的理解很深，这个可以部分的算"。
- 我们手上的实证：角色包架构（一个引擎 + N 个角色包）、人设隔离（不 OOC）、
  中日双语声线、多角色共享记忆与关系。
- 需要补的证据：**"角色一致性"要能被看见**——例如同一句话在不同角色下不会串味、
  称呼/关系可控（导师已经点到"称呼有点非主流"，这恰好是**反面证据**：
  说明这块现在还不够稳，也说明它确实是用户会介意的地方）。

### 候选 C：**IM 原生接入（微信/QQ）+ 全端共享同一份记忆** ← 是**渠道**，不是壁垒
- 导师说"这个不难"，**我同意**。它的价值在**分发与场景**（她出现在你本来就在的地方），
  不在技术门槛。⇒ 写进"体验优势"可以，**别写进"壁垒"**。

### 候选 D：手机端本身 ✗
- 导师已拆完，**不列入**。

## 四、接下来我建议怎么做（按性价比）

1. **补三个点名的对标**（仓鼠元元 / WorkBuddy×和平精英 / 大厂具体产品），
   写成一张**带来源的差异表**——这是导师要的"证据和调研"，也是我们最该先做的。
2. **把 PPT 的定位页重写为"一个窄 but 可证的 unique + 其余是支撑"**，
   而不是"我们最全"。第 7 页那份诚实定位保留，但**挪到附录/问答页**，
   开场换成主张句。
3. **加一页"预设问答"**，专门接导师这几刀：
   - 为什么上手机？→ 场景与分发（**不吹壁垒**）
   - 手机端难不难？→ 坦白：客户端不难，难的在感知与角色一致性
   - 别人为什么不做？→ 用候选 A/B 的证据回答，不用"我们最全"
4. **准备两个开场版本**（同一套内容，两种讲法）：
   - **创业/评奖版**：以"隐私友好的常驻陪伴"为核心主张；
   - **学术/自审版**：以"研究问题 + 我们的发现"为核心（对齐 UbiComp/CHI/CSCW 的写法）。
5. **人设称呼问题**：把"称呼/关系可配置"当成一个**功能**写出来（不是补丁），
   顺便把它变成候选 B 的证据之一。
6. **AR 与手部互动的定位**：降级为"能力展示"页，一句话带过，不占开场与主线。

## 五、需要用户拍板的一件事
**这份 PPT 主要讲给谁听？** 它决定"unique 点"选谁、开场怎么写：
- 若面向**导师/比赛评委/投资人** ⇒ 走候选 A（隐私友好常驻感知）+ 候选 B（二次元深度），
  故事偏"产品 + 壁垒"；
- 若面向**HCI 会议/科研汇报** ⇒ 走候选 A 当研究问题，故事偏"新模态 + 用户研究"，
  功能展示退为"原型实现"。

两者的**内容**可以共用，但**开场与主张必须换**。
