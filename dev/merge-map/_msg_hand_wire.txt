feat(hand): 把手部检测器接进 AR 相机 —— 全链路打通（不再是"没被使用的组件"）

上一提交只到了"编译通过的组件"，没有任何调用点。这一步补上调用点，功能才真的落地。

## 改动
1. `ArScreen.kt`：
   · 新增 `ImageAnalysis` 用例并绑进 `bindToLifecycle`（与 preview / ImageCapture 并列）：
       - `STRATEGY_KEEP_ONLY_LATEST` —— 只处理最新帧，绝不让检测积压拖慢预览；
       - `OUTPUT_IMAGE_FORMAT_RGBA_8888` —— 这是"自己按平面拷位图"的前提（见下）；
     · 分析器跑在 `remember { Executors.newSingleThreadExecutor() }` 的专用线程上；
     · 每帧：`HandDetector.onFrame(img, img.imageInfo.rotationDegrees)`，`finally { img.close() }`，
       `try/catch` 包住 —— **一帧检测失败绝不影响预览**；
   · 进页面 `HandDetector.init(ctx, mirrored = useFront)`（幂等）；
   · 离开页面在 `DisposableEffect` 的 `onDispose` 里 `HandDetector.release()` + `handExec.shutdown()`。
2. `HandDetector.kt`：**不再用 `ImageProxy.toBitmap()`**。
   原因：那个 API 对"是否已应用 rotationDegrees"在不同版本/机型上说法不一致，
   而 `HandTouch` 的契约要求关键点是**未旋转的原始帧**坐标（旋转/镜像由它自己完成）。
   一旦 `toBitmap()` 替我们转了，下游再转一次就是**双重变换**。
   ⇒ 改为自己按 RGBA_8888 平面逐行拷（并处理 `rowStride > width*4` 的**行尾填充**，
     否则图像会斜），保证交出去的一定是原始帧。

## 现在的链路（全部有调用点）
```
CameraX ImageAnalysis（RGBA_8888 / 只留最新帧）
  → HandDetector.onFrame → MediaPipe HandLandmarker（LIVE_STREAM，21 关键点）
  → 食指指尖换算到帧像素 → HandTracker.provider
  → VrmArScreen: HandTracker.points() → HandTouch.toScreen(旋转/镜像/FILL_CENTER)
  → 命中盒判定（头/身）→ 去抖 Latch → 触发反应
```
