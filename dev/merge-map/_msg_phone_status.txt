## 写法（刻意如此）
把每一项标成三档，**不把"编译通过"写成"功能可用"**：
  ✅ 已实现（有调用点）｜🧪 已验证（编译/单测/语法通过）｜⏳ 未验证（要真机）

## 盘点结论（摘要）
· **技术底座**：纯原生 Kotlin，无 Chaquopy/Python（全仓 0 命中、.py 0 个）；
  只用 JDK+Android SDK 即可构建成功；**145 个 JVM 单测全绿**。
· **表现层其实相当完整**（这是本轮的新认识）：Live2D 渲染/表情/动作/**命中区触摸**、
  2D 立绘 + **换装**（`PortraitView.OUTFITS = 刀服/制服/寝間着/私服`，注释写明
  "换装必须换掉身体，而不是在旧身体上叠加" —— 与桌面端排查结论一致）、装扮选择 UI、
  VRM、VRM-AR、相机 AR 拍照。**缺的不是换装**。
· **语音链路**：离线识别（SenseVoice，注意部分机型初始化会崩、代码里有门控）、
  离线合成（Kokoro）、唤醒词、VAD、录音格式，都在。
· **消息与陪伴**：微信 iLink / QQ OneBot / SSE 对话 / 记忆 / 人设 / 白名单+安静时段+调度 /
  识图 / 模型配置，都在。
· **手部互动（本次新做）**：真检测器（MediaPipe HandLandmarker）、接进相机、
  碰一下（`__poke`）、捏一下（`__pinch`，9 个单测全过）、看着我的手（`__lookAt`）；
  坐标口径统一交给 `HandTouch.toScreen`，为此不用 `ImageProxy.toBitmap()`。

## 明确的缺口（诚实清单）
1. 真机回归未做（adb 无设备）：扫码登录 → 图文/表情包收发 → 白名单 → 记忆 → 角色切换；
2. 手部互动的真机验证未做（关掉「试手」、用真手验方向与幅度）；
3. 包体 302 MB（已分析、已实删 20.34 MB；**用户指示先不管包体** ⇒ 暂缓）；
4. 手势只有"捏合"一种；握拳/挥手/比心可用同一套关键点扩展（纯函数 + 单测即可）。

## 推荐顺序
真机回归 → 手部互动真机调参 → 按需扩展手势 → 包体优化（等用户发话）。
