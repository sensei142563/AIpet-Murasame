### 3.3 关键判断（2026-10-04 修订）

C 是**手机上最接近"她"的那条线**（会动的 Live2D + 设备端向量记忆 + 自主问候），
也是**目前唯一已经把动作/表情数据化**的实现（`assets/profiles/*.json` + act 状态机设计文档）。

**但它不是我们的基线。** 修订后的判断：
- **它是一份高质量的学习材料**：读它的设计文档能省下大量试错；
- **它的做法值得学**：动作/表情数据化、act 防御性状态机、情绪三层对齐；
- **它的代码不进来**：`chatter` 里用 Kotlin **自己重写**（ADR-003 / `02-方法库.md` M9）；
- **它的表结构可以当"记忆协议"的参考蓝本**（但协议以 A+B 的互通需求为准，见 ADR-001）。

## 7. 缺口清单（要做什么，一句话版）

> 按 `00` §3 的方法层归属排列。**不含时间。**

1. **代码层（L0）**：① 密钥出源码；② 审计/测试进仓库；③ 抽"统一内核 + 通道 adapter"；
   ④ **`chatter` 是 Android 侧主工程**（本项目起源/上游是 `AIpet-Murasame-main`）——手机端一切工作进它，`live2D` 只读参考。
2. **记忆层（L1）**：① 记忆协议 v0（事件日志 + 物化视图）；② A 的散装 JSON 迁进 SQLite；
   ③ `chatter` 加记忆表；④ 检索加权补完（IDF + 时间衰减 + 重要性 + MMR）+ 50 条回归集；
   ⑤ **记忆服务：先做出来、默认关闭、设置页留入口**（D3）。
3. **手机层（L2）**：① Live2D 渲染**自己实现**；② 动作档案数据化（双轨，D4）；③ 微信通道与渲染共存；
   ④ 与桌面记忆互通；⑤ 手机 AR（VRM）。
4. **感知层（L3）**：端侧分类 + 物品识别 + 纯视觉动捕（D5）+ 事件总线 v1。
5. **实体层（L4）**：① **可携带体**（软件仿真先行）；② 功耗预算表；③ 配对与隐私；
   ④ 家里那台头**只留接口**（D9）。
6. **现实层（L5）**：智能家居（性价比最高）、机械臂（买套件）、投影（不早于 AR）。
7. **工程层（L0）**：密钥、测试、分层、**参考纪律**（仓库里不出现 `live2D` 的文件）。
8. **组织层**：与同学的接口（`00` §6）——**他方便时做硬件，你不等他**。
