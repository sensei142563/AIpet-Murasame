> 目的：把"可能让项目停下来"的东西提前写下来。技术风险可以试错，**法律与隐私风险不能试错**。
> 本文不是法律意见；涉及具体行为请咨询专业人士。文中法条以公开信息为准，**具体适用需自行核实**。

## 1. 法律与合规红线

### 1.1 声音权（最贴近本项目的一条）

**风险场景**：用某位声优/某人的声音训练音色克隆，或克隆你朋友/同学的声音让桌宠说话。

**要点**：
- 《中华人民共和国民法典》**第一千零二十三条**明确：对自然人声音的保护，**参照适用肖像权保护的有关规定**。
  即：未经许可，不得以营利或损害他人权益的方式使用他人声音（包括 AI 合成的声音）。
- 本项目现状：`pets/murasame/voices/` 里的参考音来自商业游戏角色与蔚蓝档案角色（README 已声明素材来源与版权归属）。
  **本地学习研究可以，公开发布/分发/商用不行。**

**做法**：
1. 桌宠对外发声的"默认音色"尽量用**自己录的**或**明确授权/开放许可**的音源。
2. 如果保留现有角色音色：**只在本地自用**，不随仓库分发、不放进发布包、不做直播/公开演示（或至少只演示自己录的音色）。
3. 任何人（包括朋友）的声音，克隆前先问一句并记录同意。
4. 不要把"克隆某人声音"做成产品功能提供给第三方。

### 1.2 肖像权与高拟真面部

> **2026-10-04 修订**：按 `00` §0.5 D8/D9，"硅胶体"已重新定义为**可携带的实体**（不做表情），
> 而"会做表情的头"是**以后买成品**。所以本节的风险主要落在两处：
> ① **可携带体的外观**（它会跟你进公共场所）；② 未来买成品时对**他人肖像**的处理。

**风险场景 A：可携带体的外观用了真人相貌**
（例如把玩偶的脸做成明星、同学、或任何非本人的人）

**风险场景 B：将来买成品后，用真人形象做定制外观**
（例如给成品头换上一张真人脸）

**要点**：
- 未经许可制作、使用他人肖像（包括 3D 建模、AI 换脸、实体雕塑），可能侵害肖像权。
- **《民法典》第 1019 条**：不得以丑化、污损，或**利用信息技术手段伪造**等方式侵害他人肖像权。
- 《互联网信息服务深度合成管理规定》：深度合成服务提供者需**显著标识**合成内容，不得删除/篡改标识。
- **已生效的判例（说明这不是理论风险）**：
  - AI 换脸替换原视频人物 → 侵害肖像权（网红魏某案）；
  - 换脸模板 → 侵害**个人信息权益**（廖某案，2024-06）；
  - **AI 换脸诽谤案**（张家港法院一审 2025-12）：**诽谤罪，有期徒刑 1 年 3 个月**，二审维持。
  - 汇总来源：[上海市律协专业论文](https://www.lawyers.org.cn/info/5c4949515b664a33968a9f5cb8b06a29)（见 [`04-调研附件.md`](04-调研附件.md) §3.8）

**做法**：
1. **走原创二次元风格造型**（正是你想要的），不要以真人为蓝本。
2. 唯一例外：做**你自己**的分身，且你自己同意。
3. 如果未来把任何合成内容公开（视频/直播/发帖），**明确标注"AI 生成"**。
4. **可携带体进公共场所时**，注意"别人会怎么理解这个东西"——
   它不该让人误以为是真人，也不该让人误以为在拍他。

### 1.3 数据合规（个人信息保护）

**风险场景**：常开摄像头、人脸库、录音、定位、作息习惯采集 —— 这些全是**个人信息**，部分是**敏感个人信息**（人脸、行踪）。

> **⚠ 可携带体把这条从"技术选择"变成"物理现实"**：
> 一个装着摄像头和麦克风的东西天天跟着你出门，它**必然会拍到别人、录到别人的话**。
> 你自己的项目可以随便折腾，**但别人没同意被你录**。
> 这是本套文档里**最需要你自己想清楚的一条**（见 [`07-待定选择支.md`](07-待定选择支.md) Q13）。

**要点**：处理个人信息需有合法性基础（同意等），遵循**最小必要**、**目的限定**；
向他人提供/公开需单独同意；跨境传输有额外要求。

> **重要发现（独立调研核实）**：《个人信息保护法》**第七十二条**——
> 「自然人因个人或者家庭事务处理个人信息的，**不适用本法**」。
> **含义**：
> - 你自己 + 家人用的桌宠（不对外提供服务）→ **目前不在 PIPL 管辖范围内**，合规压力小。
> - **一旦开放给陌生人使用（哪怕免费、哪怕是给同学装一个）→ 立刻落入管辖**，
>   第 24/28/29/38/39/40/47/55 条全部生效（人脸/声纹属敏感个人信息须**单独同意**；出境须安全评估/认证/标准合同三选一）。
> - **分界线是"是否对外提供"，不是"是否收费"**。这条线要一直记着。
>
> 来源与完整分析：[`04b-调研-记忆架构.md`](04b-调研-记忆架构.md) §3。

> **但第七十二条只免除"法律义务"，不免除"对别人的责任"。**
> 你带着它出门时，路人不是"你的家庭事务"。所以下面第 6 条与 §1.3.1 是**独立于 PIPL 的自律要求**。

**做法（与 ADR-007 一致）**：
1. 默认本地处理，默认不上传；上传需显式开启且界面常驻可见。
2. **记忆从写入那一刻就带 `privacy` 标签**（`local|device|lan|sync|public`，默认 `local`），
   同步层**默认拒绝**未标注记忆出设备；**由 type 查规则表决定，绝不由 LLM 决定**。
3. 不给第三方（含云 API）发送原始音视频，只发必要的最小信息；能本地做完就本地做。
4. 人脸库、录音、日记等目录**永不进仓库、永不打进发布包**（A 线已有此原则，继续执行）。
5. 提供"一键清除全部个人数据"的入口；删除后要**全网（含云端）消失**。
6. **不要采集他人数据**：摄像头拍到室友/路人时，只做"是否为主人"的即时判断，**不留存**、不识别身份。

#### 1.3.1 可携带体的四条自律要求（**推荐按此执行**）

> **2026-10-04 修订（D14）**：你选择了 **D 档要求 + 软件开关**（不做硬件开关）。
> 下面按此调整，并额外说明"软件开关"要满足什么才算合格。

| # | 要求 | 为什么 |
| --- | --- | --- |
| **1** | **不录制他人**：摄像头只在本地做即时判断，原始帧**不落盘、不上传** | 别人没同意被录。这条是底线，不是可选项 |
| **2** | **录音/拍摄时有明显指示**（LED 或提示音） | 让周围的人知道它在听/在看，避免"偷录"的误会 |
| **3** | **开关用软件实现，但必须"状态真实"** | 见下方四条硬性要求 |
| **4** | **不伪装成真人**：对外要能说明这是 AI | 既是合规（标识义务），也避免公共场合的误会与冲突 |

**软件开关必须满足的四个条件（D14 的具体化）**

| 条件 | 检验方法 |
| --- | --- |
| **关掉时硬件真的停止采集** | 不是"采了但不发"；闭源方案无法验证时，**宁可不用它自带的摄像头/麦克风** |
| **状态持久化** | 重启设备后仍然是关的（不能默认打开） |
| **可审计** | 能查到"什么时候开过、开了多久"（自己也该能查） |
| **默认关** | 采集类功能一律默认关闭，需要时手动开 |

> **一句实话（留作可选项，不阻塞）**：软件开关的失效方式是"**你不知道它在录**"，
> 硬件开关的失效方式是"**多了个零件**"。硬件开关成本很低（一个拨动开关串在摄像头供电线上），
> 你哪天想加随时可以加（`05` §6 第 7 项已记账）。

#### 1.3.2 「皮」自带的摄像头/麦克风是独立风险

按 D12，皮可能是**现成的成人向硅胶产品**——这类产品**常自带摄像头、录音与私有 App**。
**用它自带的电子件 = 把隐私交给厂商**，而且你无从审计。

**做法**：
1. **只用壳，不碰它的电路**（ADR-010 明确禁止把核的功能实现在皮里）；
2. 买之前确认：**能完全断电它自己的模块**；
3. 如果它无法断电或无法拆开 → **不买这一款**；
4. 自己核的摄像头/麦克风**不藏在皮里**（包括 LED 指示灯的可见位置，ADR-010 已写进物理接口标准）。

> **这四条与 D7 的关系**：硬件三年后才做，但**软件侧现在就要按这些设计**——
> 例如"原始帧不落盘"必须是默认行为，而不是事后加一个开关。

**这条决定的实际含义（写清楚，免得以后误解）**：
- **风险敞口已经落地（仓库与素材早已公开、不可撤回）**，只是**你接受了它**：因为 `origin` 是公开仓库，
  **任何一次 `git push` 都会把这些资产公开发布出去**。
- **前提已变（2026-10-04 复核）**：远程**早已就是 HEAD**（`git ls-remote origin main` = `9127c80` = 本地 HEAD，0 ahead / 0 behind），`origin/main` 的树里**就含** `Live2d/Live2DCubismCore.dll`、`pets/*/live2d/*.moc3` 与 20 个 `asr.txt`。→ 所以「保持现状」**不是**"在不推送的前提下成立"，而是"**已经公开、不可撤回**"：本地提交照旧，**再谈"不推送"已无意义**（`docs/handover/2026-09-24.md` 记 09-24 当天即 `origin/main == HEAD`）。
- 这条**不影响任何开发工作**（本地提交、跑代码、改东西都不受影响）。

**推荐的判断方式**：
> 问自己一句——**"我愿意让陌生人下载到丛雨的 `.moc3` 吗？"**
> 如果答案是不愿意，那么**A 就是错的**（因为远程是公开的，推上去就等于同意）。
> 这不是法律建议，只是把问题摆到你面前。
