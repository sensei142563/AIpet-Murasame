## 先把这十二条记住

1. **`AIpet-Murasame-main` 是本项目的起源/上游**（桌面主线）；**`chatter` 是它的下游衍生**（Android 端，Android 侧主工程）；微信只是她的一个通道（`00` §2.4）。
2. **`live2D` 的思路尽量复用，代码/资源/SDK 不照搬**（`03` ADR-012）。
3. **⚠ Live2D SDK 有独立的发布许可合同**——自用没事，**公开分发前必须签**（`00` §0.7）。
4. **灵魂唯一，身体多份**——桌面与手机的记忆必须打通。
5. **可携带体 = 一个核 + 可换的皮**，核是**哑巴音箱**（音色全在手机侧，`00` §2.3）。
6. **先做出来，再决定用不用**——记忆服务就是要"静默地先做好"。
7. **先仿真后实体**——硬件三年后再手搓，但软件接口与仿真现在就能全写完。
8. **双轨模型**：Live2D 是日常形态，VRM/3D 是 AR 与实体形态。
9. **语音拟人化暂时搁置**——它容易崩掉整个项目。
10. **参考纪律**：仓库里不出现别人项目的文件。
11. **不用"感觉好点了"验收，要数字。**
12. **不设时间表**——只定方法：怎么算做完、怎么算做对、卡住怎么办（见 `02`）。

## 三条硬规则

1. **一份事实只有一处**：能力在 `01`，方法在 `02`，决策在 `03`，钱在 `05`，选项在 `07`。别在别处复制粘贴。
2. **文档随代码一起本地提交**，推送由用户下令（沿用 `docs/handover/README.md` 的工程原则）。
3. **不允许出现隐私**：QQ 号、微信 ID、API Key、真人照片路径，一律不进这些文件。

## 维护节奏

- **每次拍板**：先在 `00` §0.5 追加一条 `D#`，再在 `03` 追加对应 ADR。
- **每次完成一件事**：更新 `01` 的现状（把"未测"换成数字）。
- **每次花钱**：在 `05` 记账（实际价格、渠道、用途）。
- **每次卡住又解决**：把坑写进 `02` §5.1，下次不再踩。
