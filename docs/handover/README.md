# AIpet · 交接规范（风格 / 原则 / 流程）

> 这份文档是项目的**共同记忆**：任何一方（人 / 模型）接手前先读它，交付前按第 5 节写一封交接记录。
> 最近一次交接记录：[`2026-09-24.md`](2026-09-24.md)

---

## 1. 项目一句话

AIpet 是「**一个引擎 + N 个角色包**」的桌面宠物程序：引擎负责对话、语音合成、QQ / 微信接入、
外观框架与启动器；`pets/<角色id>/` 是纯数据的角色包（人格、立绘、Live2D 模型、语音参考、
触摸区域）。换一个角色包就是换一只桌宠，**不许把某个角色的东西写进引擎**。

## 2. 目录职责（改东西前先认门）

| 路径 | 职责 |
| --- | --- |
| `main.py` | 桌宠主程序：2D / Live2D 窗口、气泡、右键菜单、拖拽、崩溃自学习 |
| `run.py` | 一键启动：依赖自检、拉起各服务（GPT-SoVITS / F5-TTS / 本地 API） |
| `api.py` + `tool/api_server.py` | 本地 HTTP API（控制端口），启动器靠它给桌宠发指令 |
| `classes/murasame_class.py` | 桌宠窗口本体：气泡文本缩放、换装菜单、输入模式 |
| `pcl_launcher/` | PyQt5 启动器：`silicon_window.py` 主窗与首页、`widgets.py` 设置页与通用控件（`BoolSwitch` / `ChoiceRow`）、`themes_panel.py` 主题页、`plugins_panel.py` 插件页、`colors.py` 配色与主题、`pet_wizard.py` 新建角色向导、`touch_editor.py` 触摸区域编辑器 |
| `pets/` + `pets/pet_registry.py` | 角色包 + 角色发现 / 能力探测（立绘、Live2D、语音、触摸） |
| `qq/` | QQ 桥（NapCat OneBot11） |
| `wechat/` | 微信桥（ClawBot iLink） |
| `tool/` | 工具：`config.py` 配置读写、`touch_areas.py` 触摸区域模型、`pack/` 打包、`api_server.py` |
| `NapCat.Shell.Windows.OneKey/` | 内置 NapCat + QQ 装载目录；`NAPCAT_VERSION.txt` 版本锚 |
| `config.example.json` | 随包默认配置 —— **新增配置键必须同步这里** |
| 自测 / 探针 / 渲染脚本 | **不进仓库**，放在仓库外的临时审计目录 |

## 3. 界面风格（启动器 + 桌宠）

- **基调**：深色亚克力 + 单一强调色；卡片式分区、统一圆角与留白。不使用裸的系统默认控件外观。
- **层级**：区块标题（图标 + 名称）→ 一行说明 → 控件。看不出层级的「一大坨设置」不接受。
- **控件按语义选**（这是硬规定，别再出现「用滑杆表示开/关」这类事）：

  | 语义 | 控件 |
  | --- | --- |
  | 是 / 否 | `BoolSwitch` 开关（状态画在控件上，左关右开） |
  | 多选一（2~4 个） | `ChoiceRow` 一排按钮，当前项高亮 |
  | 多选一（型号多 / 可自定义） | `QComboBox`（可编辑） |
  | 数值 | `QSpinBox` / `QDoubleSpinBox`；滑杆只留给真正的连续量 |
  | 文本 / 密钥 | `QLineEdit`（密钥默认打码 + 显示/隐藏） |

- **颜色有语义**：强调色 = 选中 / 主操作；紫 = 创作类（立绘工坊）；红 = 危险（删除）；
  普通操作 = 中性描边。**一行里最多一个红色。**
- **状态必须真实**：界面上显示的值来自真实配置 / 进程状态，不许"猜"，
  更不许出现「看着是开、其实没生效」。
- **文案**：中文、口语、直给；说清「会发生什么」和「为什么」；不留空话（"优化""高级""智能"）。
- **弹窗**：用户可见路径一律用自绘的主题对话框；`QMessageBox` 只留给崩溃 / 严重错误。
- **透明化**：页面块统一交给 `_make_transparent()` 压成半透明好透出主题壁纸；
  需要"必须真彩"的控件（配色色块、分段选择的选中态）打 `keep_true_color`，
  并且颜色写 `rgba(...,0.x)` **小数**形式（该函数只压实心色）。

## 4. 工程原则

1. **不推送、不动远程** —— 除非用户明确下令。日常只做本地提交。
2. **小步**：一次提交只做一件事，改动可回滚，不夹带无关重构。
3. **改完必须自证**：`py_compile` → 相关自测 → 全量自测 → 必要时截图。
   没有证据的「应该没问题」不许写进交接记录。
4. **不碰用户数据**：`config.json`、`pets/*/pet.json`、`pets/*/memory/`、
   NapCat 的 `config/ cache/ logs/ guild1.db`、各种凭据文件。
   任何探针 / 渲染脚本**先快照、跑完还原**。
5. **隐私零泄漏**：QQ 号、微信 ID、API Key、NapCat WebUI token、本机绝对路径，
   都不许进仓库文件、提交信息、日志、截图；日志里的 token 打码。
6. **配置键向后兼容**：优先复用已有键；新增键必须同时更新 `config.example.json`、
   设置页、README —— 三处缺一不可。示例配置里**不许有没人读的键**
   （摆着就是骗用户去改一个没用的东西），`test_config_defaults.py` 会拦。
7. **单一定义**：不留重复函数、同名方法、死代码、孤儿 import；提交前跑一遍扫描器。
8. **能力默认关**：新玩法对没配置的角色 / 用户默认不生效
   （例：没做过触摸区域的角色不响应触摸；协作者的插件默认全部停用）。
9. **版本锚定**：NapCat / QQ 的版本写进 `NAPCAT_VERSION.txt`，
   让打包检查、README、启动器三处一致。
10. **打包与源码分离**：不打包时不去动 `dist/`，也不假装修好了；
    真要打包走 `tool/pack/`。

## 5. 交接文档规则（硬性）

- 每次交接 —— 我方一次会话结束、对面一次交付 —— **必须**在 `docs/handover/` 放一封
  `YYYY-MM-DD.md`；一天交接多次用 `YYYY-MM-DD-2.md` 顺延。
- 必含字段见第 6 节模板，**不许省**。事实优先：不确定就写「未验证」，
  不许写「应该没问题」。
- 交接文档随代码一起**本地提交**；**推送由用户下令时统一推送**（含交接文档），
  未经下令一律不推。
- **对面（协作模型 / 协作者）同样适用**：每次交接写一封放进同一目录，
  等用户说推送时一起推送。
- 交接文档里同样不许出现隐私信息（见原则 5）。

## 7. 常用命令（本机）

```powershell
# 全量自测（脚本在仓库外的临时审计目录）
python run_all_tests.py             # 全部（约 60 秒）
python run_all_tests.py touch       # 只跑文件名含 touch 的
python run_all_tests.py --list      # 只列清单

# 单跑一个自测
python test_choice_rows.py

# 语法检查（改完任何 .py 先跑这个）
python -m py_compile pcl_launcher\widgets.py
```

- **解释器**：开发机用系统 Python 3.10（PyQt5 + torch cu128 + f5_tts）；
  仓库 `.venv` 是**打包用**（CPU 版 torch + PyInstaller），两者别混。
- **审计目录**：仓库外，里面有全部自测 `test_*.py`、探针 `probe_*.py`、
  渲染 `render_*.py`、扫描器 `scan_*.py`、跑测器 `run_all_tests.py`。
  它**不随仓库走** —— 换机器只剩仓库里的东西，测试需要重建（这是当前已知的短板）。
  常用审计脚本（都在审计目录里，直接 `python xxx.py`）：
  `audit_settings_wiring.py`（设置页有没有"摆了没人读"的开关）、
  `audit_silent_failures.py`（用户点了却只在控制台报错的 except）、
  `scan_config_defaults.py`（同一个键的默认值在各处是否一致）、
  `audit_config_keys.py`（配置里的孤儿键）。
- **渲染页面**：`python render_pages.py` 会把启动器 7 个页面各渲一张 PNG
  （渲染前快照、渲染后还原 `config.json` / `pet.json`）。
- **Windows 控制台坑**：本机 shell 是 PowerShell 5.1（GBK 控制台）。
  中文乱码、UTF-16 重定向、`$LASTEXITCODE` 被 stderr 污染这些问题都踩过，
  照 `windows-powershell-traps` 那份笔记的写法来。

## 8. 动界面之前的自检

- **往界面上加一整块东西**（新板块 / 新卡片 / 新入口）**必须先问用户一句再动手** ——
  用户明确要求过（此前首页加「开始使用」引导卡被判定为"弄巧成拙"）。
- **别主动"美化"用户没让改的页面**：提示词页被我改成卡片式（卡片分组 + 字数状态行 +
  固定底部按钮），用户的反馈是「**不好看，用原来的**」→ 已在 `81bebf3` 回退。
  判断标准：
  * 修 bug、统一控件类型、补状态 / 失败反馈 → 可以直接做；
  * **重新排版一整页**、加卡片 / 状态行 / 固定栏这类"设计感"改动 → 先问，或干脆不做；
  * 页面信息本来就单一（例如提示词页就是两个文本框）时，**直排最好**。
- 改完的页面要能自己看一眼：`render_pages.py` 出图，别只靠"代码上应该对"。
